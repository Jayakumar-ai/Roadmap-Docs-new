This screen is used to define the application control details of Sales order management.

Navigation Path

Supply Chain \ Sales \ Setup \ Setup-Sales \ Appl.ctrl-Sales

Account

  • Sales Account - Net Sales: If discount % is set for the Sales, the amount is deducted from the total amount and Journal will be created after deduction. But the deduction is not mentioned in the Journal. Gross Sales: If discount % is set for the Sales, the amount is deducted from the total amount and Journal will be created. A separate line will be displayed in the journal to indicate the discount deduction.
  • Sales Account Level - The type of account on which the sales invoice should be created. It is categorized as Unit: The sales invoice is created based on the class/subclass definition for the unit defined in the Application accounts. Unit: Area Wise: The sales invoice is created based on the class/subclass definition for the Area wise defined in the Application accounts. Unit: Territory Wise: The sales invoice is created based on the class/subclass definition for the Territory wise defined in the Application accounts.
  • Sales Rounded Off - The Round off values for the Tax charges if decimal values exist while creating the sales invoice journal is defined here for ED, CESS, SHEC, VAT/CST, Service tax, CESS on Service tax, SHEC on Service tax, GST Decimal Service Tax.

Sales Invoice

  • Allow to create Date wise invoice - The Sales Invoice document created sequentially based on the Date if the flag is checked. If unchecked, the sales invoice is created irrespective of the date.
  • Allow to cancel Sales Invoice - If the flag is checked, the sales invoice can be cancelled even after generating the invoice number else the sales invoice cannot be cancelled.
  • No Financial Implications - When the document is invoiced, the financial processes for the invoice will be implicated only when the flag is unchecked.
  • COGS Journal Rqrd. - If the flag is checked, Price Journal will be created against the Sales Account. Cost Of Goods Journal is only applicable for Perpetual Type.
  • Fixed Asset Rqrd. - If the flag is checked, Fixed Asset should be created for Item against Class type Fixed Asset.
  • Shipset Line Stock Required - If the flag is checked, the stock is required for the Shipset Line Items.
  • Sales Invoice Cre. Based on Cust. PO - If the flag is checked, The Customer PO Number and PO date is required for the Sales Invoice document.
  • STO Cons. Rqrd - If the Flag is checked, then the Stock Transfer Order is required for the consumption items.
  • Cust PO Rqrd - If the Flag is checked, then the PO number should be given in the Invoice document.

Sales Order

  • SO to Invoice Price Check (Open Order) - If the flag is checked, the current open Order price is considered and the SI is created for the current open order Price. For example: Open order is created for FG1001 of Price Rs. 100 for the date 01.04.2024 to 31.05.2024. Create Sales Order on 01.05.2024. The price for the item is taken as Rs. 100. Amend the open Order on 15.05.2024 and increase the price as Rs.200. Now create SI for the SO, the price of Rs. 200 is taken for invoice if the flag is Checked. Now create SI for the SO, the price of Rs. 100 is taken for invoice if the flag is Unchecked.
  • SO/CS to Inv (Stock Req.) - If the flag is checked, the stock quantity of the item will be checked before creating invoice for the sales order / customer schedule. Else the stock qty will not be checked and invoice can be created.
  • Allow Completed SO - If flag is enabled, Completed Sales Order Details Also shown in the purchase.
  • Cust PO Rqrd - If the Flag is checked, then the PO number should be given in the Invoice document.

Customer Schedule

  • Hold Customer Schedule - If number of schedules created for the customer and none of the schedule is invoiced, this control will not allow creating the invoice for further schedules for the customer if checked. Else, the invoice can be created for the customer schedule.
  • Customer Schedule - Week: While creating the customer schedule, if the bucket type is specified as Week, the configuration done here in the application control is considered. If the control is assigned as Start – Schedules will be created for the start of the Week. End – Schedules will be created for the end of the Week. Not Applicable – Schedule generation may not consider the control defined. Month: While creating the customer schedule, if the bucket type is specified as Month, the configuration done here in the application control is considered. If the control is assigned as Start – Schedules will be created for the start of the Month. End – Schedules will be created for the end of the Month. Not Applicable – Schedule generation may not consider the control defined.

Sales Return

  • Allow Sales Rtn. To Pend Invoice - Once the Sales order is invoiced, when the customer returns the order qty partially, as like PO closure property, the Sales order remains pending in SOM1087 (Pending SO). The Order will be closed only when there is no return of qty from the customer. Hence if the customer returns the Qty, SO will be displayed in the Pending SO screen only if the flag is enabled else the SO will be closed and not displayed in SOM1087.
  • Upd. Price in Sales Rtn - During Sales Return if the price is to be amended this flag can be checked.

Duty Drawback

  • Option can be selected whether the duty drawback document to be created Manually or automatically.

Credit Limit

  • Credit Limit can be set against the customer in the customer master to define the number of invoices and the amount limit that can be made by the customer, wherein the checkbasis allows whether to check only on Sales invoice or both on Sales order and Invoice accordingly the action can be made against it such as to define the work flow or to stop the process.

Update Application Control

  • To make any changes in the setup, click the Update button and the screen will be redirected to the find screen.
  • Click the button to make the changes and the screen will be redirected to the application control screen where user can see the old setup and the changes can be made in the new setup.
  • Make the necessary changes.
  • Click the save button.
  • Click the post button and the document will be forwarded for approval.

Workflow Approval Process

  • To process the document in Workflow approval, navigate to the approvals screen.
  • Click View Details to view the selected document.
  • Screen will navigate into query screen to check the details.
  • Now navigate back to the approval screen.
  • Select the Approval/forward/Return/Wait radio button and click Process button to perform the corresponding Workflow process on the selected document.
